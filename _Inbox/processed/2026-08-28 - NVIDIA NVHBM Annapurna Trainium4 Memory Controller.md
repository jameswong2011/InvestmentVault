# NVIDIA Moves Memory Controller Into HBM Stack (NVHBM) — Annapurna First

**Source:** https://convergedigest.com/nvidia-nvhbm-nvlink-fusion-custom-hbm-aws-trainium4
**Date:** 2026-08-26 · **Brief score:** 10 · **Tags:** daily-intel-triage

## Why it matters (portfolio)
Mechanism + first customer beyond NVIDIA blog: controller-in-base-die vs HBM4E; multi-vendor standard; Annapurna/Trainium4. Touches **NVDA** (Fusion lock-in), **MRVL** (Trainium/networking adjacency), **000660** (custom HBM base-die qualification path).

## Article body

NVIDIA is extending its NVLink Fusion architecture deeper into the memory subsystem with NVHBM, a custom high-bandwidth memory technology designed for hyperscalers building semi-custom AI accelerators. NVHBM moves NVIDIA’s memory controller from the XPU compute die into the HBM base die, freeing silicon area for additional compute while increasing memory bandwidth and reducing power. NVIDIA says the architecture can deliver up to 30% greater memory bandwidth, 15% lower HBM power consumption and up to 25% more available XPU compute-die area compared with standard HBM4E. Amazon’s Annapurna Labs will be the first announced customer to collaborate with NVIDIA on NVHBM alongside its adoption of NVLink Fusion for future AWS silicon. The architectural change addresses an increasingly important constraint in custom AI accelerator design: the amount of expensive leading-edge silicon devoted to functions surrounding the compute engines. Conventional HBM implementations place the memory controller on the XPU die. NVHBM instead integrates NVIDIA’s custom controller into the base die of the 3D HBM stack. NVIDIA plans to establish a standard NVHBM implementation validated and supplied by multiple memory providers, giving NVLink Fusion customers a common memory architecture rather than requiring separate controller integration and qualification for each supplier. The company says NVHBM is based on the same memory technology it intends to use with future NVIDIA GPUs. For AWS, NVHBM extends a collaboration announced in December 2025 when AWS committed to integrating NVLink Fusion with its custom silicon roadmap. Annapurna Labs plans to support NVLink Fusion beginning with Trainium4, allowing AWS-designed accelerators and NVIDIA GPUs to operate within a common rack-scale architecture. NVLink Fusion gives partners access to NVIDIA NVLink chiplets, NVLink-C2C, NVLink Switches, MGX systems and racks, while supporting third-party CPUs and XPUs. Adding NVHBM means NVIDIA is now offering another key building block of that semi-custom architecture: not only the scale-up fabric connecting processors, but an HBM subsystem designed to reduce the amount of accelerator silicon required for memory control. When NVIDIA introduced NVLink Fusion in May 2025, the central proposition was that hyperscalers could retain their own CPUs or XPUs while connecting them into NVIDIA’s NVLink scale-up architecture and broader rack-scale ecosystem. The subsequent AWS Trainium4 commitment demonstrated how a hyperscaler-designed accelerator could participate in that architecture. NVHBM now pushes NVIDIA IP onto another critical boundary of the custom XPU: the interface between compute silicon and high-bandwidth memory. Moving the memory controller into the HBM base die is particularly significant because leading-edge compute-die area is one of the most valuable resources in an AI accelerator. If the controller and associated interface circuitry consume less XPU area, designers can allocate more of the die to workload-specific compute. The approach also reflects the increasing importance of advanced packaging and 3D integration: architectural functions that historically resided on the primary processor die can increasingly be distributed among chiplets, I/O dies and stacked-memory components. The broader direction is toward vertically integrated but heterogeneous AI infrastructure. NVIDIA is supplying more of the common architecture — NVLink scale-up connectivity, Spectrum-X or InfiniBand scale-out networking, MGX rack infrastructure, software and now NVHBM — while hyperscalers retain the ability to design workload-specific XPUs. That model puts NVLink Fusion between fully proprietary accelerator systems and NVIDIA&#8217;s own GPU platforms. AWS&#8217;s Trainium4 program will therefore be an important implementation to watch because it combines hyperscaler-designed compute with NVIDIA interconnect and, potentially, NVIDIA-defined memory technology within the same rack-scale architecture.
